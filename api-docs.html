Burse API v1

A REST API for connecting Burse to earned-wage-access providers, accounting software, or your own internal systems — reading payroll and bookkeeping data, and recording salary advances.

Base URL

https://pnpfurfodmejdggnyjof.supabase.co/functions/v1/api-v1

Authentication

Every request needs an API key in the Authorization header. Create one from Settings → API in Burse Payroll — the raw key is shown once, at creation time, and never again.

Authorization: Bearer bk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Each key is scoped to one company and a fixed set of permissions (scopes). Requesting an endpoint your key doesn't have the scope for returns 403. Requests are rate-limited to 120/minute per key — going over returns 429.

Scopes

ScopeGrants
readRead employees, pay runs, payslips and current-period earnings
advances:writeRecord a salary advance (EWA draw) against an employee
bookkeeping:readRead the chart of accounts and journal
bookkeeping:writePost journal entries and record expenses

Payroll

GET /employees read

Returns the company's employee roster. Sensitive fields (ID number, tax number, banking details, salary) are deliberately excluded from this list — use /payslips for compensation figures.

curl https://pnpfurfodmejdggnyjof.supabase.co/functions/v1/api-v1/employees \
  -H "Authorization: Bearer bk_live_..."
{ "employees": [ { "id": "...", "employee_number": "EMP001", "full_name": "Jane Doe",
    "job_title": "Sales Rep", "department": null, "employment_type": "permanent",
    "pay_frequency": "monthly", "active": true, "start_date": "2024-01-15", "end_date": null } ] }
GET /payroll-runs read

The company's last 50 pay runs, most recent first.

{ "payroll_runs": [ { "id": "...", "period_start": "2026-07-01", "period_end": "2026-07-31",
    "pay_date": "2026-07-25", "frequency": "monthly", "status": "finalized",
    "tax_year": "2026/2027", "finalized_at": "2026-07-24T09:12:00Z" } ] }
GET /payslips?run_id=... read

Payslips for a given run, or pass ?employee_id=... instead for that employee's last 24 payslips.

GET /earnings/current?employee_id=... read

The primary endpoint for earned-wage-access (EWA) integrations. Returns how much of the employee's basic salary has been earned so far in the current open pay period, pro-rated by calendar days elapsed, along with any advance already drawn this cycle.

{ "employee_id": "...", "full_name": "Jane Doe", "has_open_period": true,
  "run_id": "...", "period_start": "2026-07-01", "period_end": "2026-07-31",
  "days_elapsed": 7, "total_days": 31, "basic_salary": 20000,
  "earned_to_date": 4516.13, "already_advanced_this_cycle": 1500,
  "available_to_advance": 3016.13,
  "note": "earned_to_date is pro-rated on basic_salary only (calendar days), and does not include allowances, bonuses or statutory deductions. available_to_advance is advisory — you decide the actual cap." }

If no pay run has been created yet for the period covering today, has_open_period is false and no figures are returned.

POST /advances advances:write

Records a salary advance against an employee. It's automatically deducted in full from their next payslip via Burse's existing loan/advance mechanism — no separate reconciliation step needed. If the employee already has an advance outstanding this cycle, the new amount is added to it rather than creating a second one.

curl -X POST https://pnpfurfodmejdggnyjof.supabase.co/functions/v1/api-v1/advances \
  -H "Authorization: Bearer bk_live_..." -H "Content-Type: application/json" \
  -d '{"employee_id": "...", "amount": 1500, "label": "EWA draw"}'
FieldDescription
employee_idRequired. Must belong to your company.
amountRequired. A positive number, in Rand.
labelOptional. Shown on the employee's payslip. Defaults to "Salary Advance".

Bookkeeping

GET /bookkeeping/accounts bookkeeping:read

The company's chart of accounts.

GET /bookkeeping/journal bookkeeping:read

The last 100 journal entries, with their lines.

POST /bookkeeping/journal-entries bookkeeping:write

Posts a manual, balanced double-entry journal entry. Rejected if debits and credits don't match exactly.

curl -X POST https://pnpfurfodmejdggnyjof.supabase.co/functions/v1/api-v1/bookkeeping/journal-entries \
  -H "Authorization: Bearer bk_live_..." -H "Content-Type: application/json" \
  -d '{
    "entry_date": "2026-07-07",
    "description": "Office supplies",
    "lines": [
      { "account_id": "...", "debit": 500, "credit": 0 },
      { "account_id": "...", "debit": 0, "credit": 500 }
    ]
  }'
POST /bookkeeping/expenses bookkeeping:write

Records an expense against an expense-type account — posts the matching journal entry automatically.

{ "expense_date": "2026-07-07", "vendor": "Telkom", "account_id": "...",
  "amount": 850, "vat_amount": 127.50, "description": "July connectivity" }

Errors

StatusMeaning
400Bad request — missing or invalid field. See error in the response body.
401Missing, invalid or revoked API key.
403Your key doesn't have the scope required for this endpoint.
404The resource (employee, run, endpoint) doesn't exist or isn't yours.
429Rate limit exceeded (120 requests/minute per key). Back off and retry.
Keep your API key secret — anyone with it has scoped access to your company's payroll and bookkeeping data. Revoke a key immediately from Settings → API if it's ever exposed.
